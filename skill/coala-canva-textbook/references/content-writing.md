# Instructional writing guide

- Write for the learner level provided by the user.
- Introduce difficult ideas with a familiar example before formal terminology.
- Prefer the progression: concept, example, visual or structured representation, practice, summary.
- Define a technical term the first time it appears and include its English name only when useful.
- Keep sentences and paragraphs short enough to scan comfortably at 28 pt.
- Use `~할 수 있다` for learning objectives and `~해봅시다` for guided activities when appropriate.
- Make the input, learner action, and expected result visible in each practice activity.
- Preserve required technical accuracy while simplifying wording.
- Do not add invented facts, citations, institutional claims, software behavior, or learning outcomes.
- If supplied content is too long for the requested page count, identify what must be shortened and ask for a content decision. Do not hide the conflict through smaller layout.
- If no manuscript is supplied, create an outline only for planning requests. Draft full content only when the user asks for authoring, and distinguish drafted material from user-supplied source text.

## Page planning rule

Draft the learning sequence before layout. Assign each page one primary purpose and move secondary detail to a continuation page. Repeated context may be shortened, but required source meaning must remain intact.

## Session page planning

The reference contains 102 pages across 15 sessions, an overall average of about 6.8 pages per session including front matter, divider pages, and ending pages. Use 6–7 pages only as an initial planning reference, never as a maximum or a reason to compress content. Increase the page count whenever the confirmed typography, screenshot readability, or whitespace rules require it.
