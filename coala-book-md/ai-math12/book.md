# 바이브프로젝트1
## 화면을 배치하고 말로 동작 만들기

### 학습 목표

- GUI가 무엇인지 설명할 수 있다.
- 버튼, 입력창, 라벨, 글을 보여 주는 공간의 역할을 구분할 수 있다.
- 앱 화면이 여러 위젯으로 이루어져 있음을 설명할 수 있다.
- 위젯의 위치와 역할을 정해 간단한 앱 화면을 설계할 수 있다.
- 버튼을 누를 때마다 색이 바뀌는 앱을 만들 수 있다.
- 메시지를 새 줄로 추가하고 입력창을 비우는 앱을 만들 수 있다.

### GUI란 무엇일까요?

앱에서 버튼을 누르거나 글자를 입력해 본 적이 있나요? 사용자가 **화면을 보면서 앱을 조작하고 결과를 확인하는 방식**을 **GUI**라고 합니다.

GUI는 **Graphical User Interface**의 줄임말입니다. 쉽게 말해 **눈으로 보고 조작할 수 있는 앱 화면**입니다.

이번에는 화면에 필요한 요소를 놓고, 어떤 동작을 할지 말로 설명해 봅시다. 먼저 무지개 버튼을 만들고, 이어서 입력한 메시지를 보여 주는 채팅창을 만듭니다.
:::

# 위젯으로 앱 화면을 만들어요

버튼이나 입력창처럼 앱 화면을 이루는 작은 구성 요소를 위젯이라고 합니다. 필요한 위젯을 골라 놓으면 앱의 기본 모양을 만들 수 있습니다.

위젯을 배치하는 공간은 디자이너입니다. 어디에 놓을지 정하는 것이 화면 설계이고, 눌렀을 때 무엇을 할지 정하는 것이 동작 설계입니다.

| 화면에서 보는 것 | 하는 일 |
|---|---|
| 버튼 | 누르면 정해진 동작을 시작 |
| 입력창 | 사용자가 글자나 숫자를 입력 |
| 라벨 | 제목, 이름, 메시지 입력 같은 짧은 안내를 표시 |
| 여러 줄의 글을 보여 주는 공간 | 설명, 결과, 메시지를 여러 줄로 표시 |

> [!KEY_POINT]
> 라벨은 화면의 안내 글을 말합니다. Text를 짧은 안내 글로 쓸 수도 있고, 입력창에 붙은 안내 글도 라벨이라고 부릅니다.
:::

# 바이브프로젝트의 다섯 단계

버튼 클릭처럼 앱에서 일어나는 일을 이벤트라고 합니다. 이벤트 입력칸에는 그 일이 일어났을 때 앱이 무엇을 해야 하는지 적습니다.

앱의 모양과 동작을 다음 다섯 단계로 준비해 봅시다. 마지막에는 프로젝트 생성 버튼을 눌러 코드를 만들고 실행합니다.

| 단계 | 무엇을 하나요? |
|---|---|
| ① 프로젝트 정보 | 프로젝트 이름과 앱 설명을 적습니다. |
| ② 위젯 | 오른쪽에 위젯을 추가하면 왼쪽 목록에 자동으로 나타납니다. |
| ③ 이벤트 | 버튼을 눌렀을 때 할 일을 적습니다. |
| ④ 추가 설명 | 더 정하고 싶은 규칙을 적습니다. 필요 없으면 비워 둡니다. |
| ⑤ 프로젝트 생성 | 프로젝트 생성 버튼으로 코드를 만든 뒤 실행합니다. |

> [!TIP]
> 위젯을 놓고 동작을 설명한 뒤, 생성·실행하여 확인하세요.
:::

# Button으로 무지개 버튼 만들기

**Button**은 누르면 확인이나 계산 같은 기능을 실행하는 위젯입니다. 이름은 **btn1, btn2, …**처럼 만들어집니다.

이번에는 버튼을 누를 때마다 **빨강, 주황, 노랑, 초록, 파랑, 남색, 보라** 순서로 색이 바뀌는 앱을 만듭니다. 마지막 색 다음에는 처음부터 반복하게 해 봅시다.

이제 화면을 따라 버튼의 동작을 만들어 봅시다.

> [!TIP]
> btn1은 위젯 이름, Button은 버튼 위에 보이는 글자입니다. 이벤트를 적을 때 어떤 버튼인지 이름을 확인하세요.

- [ ] 버튼을 추가하고 원하는 위치로 옮길 수 있다.
- [ ] 클릭했을 때 할 일을 짧게 설명할 수 있다.
- [ ] 프로젝트를 실행하여 색이 바뀌는지 확인할 수 있다.
:::

# 입력할 곳과 보여 줄 곳 구분하기

## ② Field: 한 줄로 입력하는 곳

글자나 숫자를 한 줄로 입력하는 위젯입니다. 아이디 입력칸을 떠올려 보세요. 이름은 **fld1, fld2, …**처럼 만들어집니다.

## ③ Text: 여러 줄의 글을 보여 주는 곳

설명, 계산 결과, 메시지를 여러 줄로 보여 주는 위젯입니다. 이름은 **txt1, txt2, …**처럼 만들어집니다.

# 그 밖의 위젯도 살펴봐요

위젯 목록에는 여러 역할의 구성 요소가 있습니다. 어떤 일을 하는지 간단히 살펴봅시다.

## 선택할 때

- **Check**: 항목을 체크하거나 해제합니다. 알림 받기처럼 여부를 고릅니다.
- **Radio그룹**: 여러 선택지 중 하나를 고릅니다. Radio는 그룹 안의 선택 항목입니다.

## 값을 조절할 때

- **Slider**: 손잡이를 움직여 음량 같은 값을 조절합니다.
- **Switch**: 켜기와 끄기를 전환합니다.

## 화면과 진행 상태를 보여 줄 때

- **Box**: 위젯을 담거나 화면의 구역을 나눕니다.
- **Progress**: 작업이 얼마나 진행되었는지 보여 줍니다.

# 입력한 메시지가 쌓이는 채팅창 만들기

이번에는 **한 줄로 메시지를 입력하고 버튼을 누르면, 아래에 메시지가 한 줄씩 쌓이는 앱**을 만듭니다. 어디에 입력하고, 무엇을 누르고, 어디에서 결과를 볼지 정해 봅시다.

앞서 놓은 버튼을 활용하고 Field 하나, Text 하나를 추가합니다. 프로젝트 정보도 새 동작에 맞게 바꾸고, 각 위젯의 위치를 직접 정합니다.

> [!TIP]
> 같은 버튼을 이어서 쓴다면 무지개색으로 바꾸던 이벤트 설명을 메시지를 보내는 설명으로 교체하세요. 위젯 이름이 예시와 다르면 실제 이름을 사용합니다.

- [ ] 입력창, 버튼, 메시지를 보여 줄 공간을 배치할 수 있다.
- [ ] 버튼을 눌러 메시지를 새 줄에 추가할 수 있다.
- [ ] 이전 메시지는 남기고, 보낸 뒤 입력창을 비울 수 있다.
:::

# 채팅창 화면 먼저 설계하기

프로젝트 이름은 간단한 채팅창, 앱 설명은 입력한 메시지를 버튼으로 보내면 아래에 한 줄씩 쌓이는 앱으로 적어 봅시다.

아래처럼 입력창 옆에 버튼을 놓고, 아래쪽에는 여러 줄이 보일 공간을 남깁니다. 위젯을 직접 옮기며 사용하기 편한 화면을 만들어 보세요.

| 위젯 | 놓을 곳 | 할 일 |
|---|---|---|
| Field: fld1 | 위쪽 왼쪽 | 보낼 메시지 입력 |
| Button: btn1 | 입력창 오른쪽 | 메시지를 Text에 추가 |
| Text: txt1 | 아래쪽 넓은 공간 | 메시지를 여러 줄로 표시 |

> [!KEY_POINT]
> 입력할 곳, 누를 곳, 결과를 볼 곳을 구분하세요. Text에는 여러 줄이 보일 공간을 남기고, 현재 위젯 이름이 fld1, btn1, txt1인지 확인합니다.
:::

:::page{type="concept" id="ch12-chat-event" layout="basic"}
# 버튼에 메시지 보내는 동작 연결하기

## 추가한 뒤 입력창 비우기

Button의 **클릭 시** 이벤트에는 다음 순서로 할 일을 적습니다. 앞서 적은 색 바꾸기 설명이 있다면 바꾸어 주세요.

```flow
Field | 입력 읽기
Text | 새 줄에 추가
Field | 입력 비우기
```

- Field에서 보낼 내용을 읽습니다.
- Text의 **이전 글은 남겨 두고 새 줄에 추가**합니다.
- 추가한 다음 **Field를 비웁니다.**

## 이벤트 요청문 예시

버튼을 누르면 fld1의 내용을 txt1의 기존 글 아래에 새 줄로 추가해 줘. 추가한 뒤 fld1을 비워 줘.

설명을 적은 다음 **프로젝트 생성**, **생성된 코드 보기 / 실행**, **실행** 순서로 앱을 실행합니다.

> [!KEY_POINT]
> 입력값을 먼저 지우면 보낼 내용을 잃을 수 있습니다. Text에 메시지를 추가한 다음 입력창을 비우도록 설명하세요.
:::

# 직접 보내며 완성된 동작 확인하기

## 완성 예시와 비교하기

::image{src="assets/프로젝트완성물.png" alt="위쪽 왼쪽에 Field 입력창, 오른쪽에 Button, 아래에 Text가 있는 채팅창 예시. 안녕하세요와 제 이름은 ooo라고 합니다라는 두 메시지가 서로 다른 줄에 남아 있다" ratio="1.702128" width="text" caption="입력한 문장이 아래에 한 줄씩 쌓이는 채팅창 예시"}

- Text에 문장이 나타나고 **Field가 비워지는지** 확인합니다.
- 다른 문장을 입력하고 다시 버튼을 누릅니다.
- 첫 문장은 그대로 남고, 두 번째 문장은 **새 줄**에 추가되는지 확인합니다.

여러 번 보내도 이전 글이 남고 입력창은 비워지는지 확인하세요. 원하는 대로 되지 않으면 해당 동작을 짧게 고쳐 설명하고 다시 생성·실행해 봅시다.
