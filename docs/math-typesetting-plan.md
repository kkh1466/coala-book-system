# Canva 교재 수식 조판 기능 구현 계획

작성일: 2026-10-27

## 구현 결과

- `concept layout="basic"`의 독립 수식 블록, 한글을 포함한 SVG 조판, 오류 위치 보고, 생성 전 준비, 실제 치수 배치, CLI 및 원고 작성 스킬 반영을 완료했다.
- MathJax 3.2.2, OpenType.js 1.3.4, fflate 0.8.2와 프로젝트에 포함한 Wanted Sans Regular를 사용한다. 수식 및 글꼴 파일의 외부 서버 호출은 없다.
- 기존 412개, 수식 관련 36개, 페이지 분량 재배분 관련 7개를 포함한 테스트 455개(34 suites), ESLint, TypeScript 검사, production 빌드가 통과했다. 빌드 번들은 4.81MB로 5MB 제한 안에 있다.
- 수식 기능의 초기 구현에서는 기존 원고 18개의 배치를 비교했다. 이후 수식 뒤 여백 및 연속 페이지 분량 재배분을 반영했다. 최종 원고·예제 19개가 검증을 통과하며, 분량 재배분 전후 페이지 수와 쪽번호 범위는 모두 동일하다. 이미지 자리 예제에서는 소제목 그룹과 이미지의 페이지 이동이 보고에 반영된다.
- 4단원 주요 수식 5개를 변환했으며, 사용자 피드백에 따라 수식 뒤에 56px 여백을 추가했다. 여백 반영 후 17장, 33~49쪽이다. 짧은 마지막 해설만 남던 연속 페이지에는 데이터 계산 섹션을 함께 배치하도록 분량을 재배분한다. 한글 분수·루트·정렬 등식의 로컬 SVG 렌더링도 확인했다.
- 사용자의 요청에 따라 실제 Canva 화면 조작과 Canva PDF 출력 확인은 사용자가 진행한다. 아래 단계 1의 Canva 수용·빈 첫 페이지·PDF 확인 항목은 사용자 테스트 대기이며, 자동 검사 통과와 구분한다.
- 빠른 확인 원고: `test-input/math-smoke.md`(수식 4개, 1장). 앱 새로고침 후 이 파일을 선택해 생성한다. 이미지 폴더는 필요 없다. 확인 항목은 `canva-app/TESTING.md`의 "수식 조판 수동 검증"에 있다.


## 1. 목표와 제작 흐름

`notes.md`를 바탕으로 `book.md`를 작성하고, Canva 앱에서 원고를 읽어 교재를 생성할 때 수식을 자동으로 조판한다. 사용자가 수식 이미지를 별도로 준비하거나 Canva에서 분수선과 지수를 직접 배치할 필요가 없도록 한다.

목표 결과는 교과서처럼 위아래로 배치되는 분수, 거듭제곱과 아래첨자, 루트, 집합 기호, 조건부 확률이다. 한글 설명이 들어간 분수도 필수 지원 대상이다.

예정된 생성 순서:

```text
notes.md
  → 원고 작성 규칙에 따라 book.md 작성
  → 앱에서 원고 및 수식 검사
  → 모든 수식을 SVG와 실제 크기로 준비
  → 수식 크기를 반영하여 페이지 분할·쪽번호 확정
  → Canva 교재 페이지 생성
```

수식은 Canva의 이미지 요소로 배치한다. Canva에서 수식 전체의 위치와 크기를 조절할 수 있으며, 식의 내용은 원고에서 수정하여 다시 생성한다. 수식 글자를 Canva의 일반 텍스트처럼 직접 편집하는 기능은 이번 범위에 포함하지 않는다.

## 2. 현재 코드에서 확인한 연결 지점

| 역할 | 현재 파일 | 필요한 변경 |
| --- | --- | --- |
| notes.md → book.md 작성 규칙 | `skill/coala-canva-textbook/SKILL.md`, `references/manuscript-authoring.md`, `references/manuscript-format.md` | 수식 작성법·배치 위치·지원 범위 추가 |
| 원고 문법과 원본 행 번호 검사 | `canva-app/src/parser/markdown-book.ts`, `manuscript-lint.ts` | 수식 영역 인식 및 오류 보고 |
| 본문 블록 파싱 | `canva-app/src/parser/blocks.ts` | 수식 전용 블록 추가 |
| 본문 요소 측정·배치 | `canva-app/src/layout/content-flow.ts`, `flow.ts` | 수식을 독립적인 흐름 조각으로 배치 |
| 페이지 분할과 쪽번호 | `canva-app/src/builder/layout-book.ts` | 수식의 실제 크기를 받은 뒤 배치 실행 |
| Canva 생성 진입점 | `canva-app/src/builder/create-book.ts`, `src/app.tsx` | 생성 전 수식 준비·진행 상태·오류 연결 |

현재 인라인 파서는 글자와 굵은 강조만 처리한다. 이미지 요소는 이미 `dataUrl`을 사용해 생성하고 있으므로 수식도 이 경로를 우선 검증한다. 다만 실제 Canva에서 MathJax SVG를 수용하는지는 별도 확인이 필요하다.

## 3. 첫 구현의 범위와 원고 문법

첫 구현은 `concept layout="basic"` 본문에서 별도 줄에 놓는 수식 블록을 지원한다. 사용자가 제시한 긴 한글 분수와 루트 수식을 이 형태로 해결한다.

수식은 독립된 `$$` 줄로 여닫는다. 스타일·좌표·이미지 파일 경로는 원고에 적지 않는다.

```markdown
:::page{type="concept" id="ch04-probability" layout="basic"}
# 확률의 기본식

## 사건이 일어날 확률

사건 A가 일어날 확률은 다음과 같이 나타냅니다.

$$
P(A)=\frac{\text{사건 A가 일어나는 경우의 수}}{\text{일어날 수 있는 모든 경우의 수}}
$$

전체 100일 중 비가 온 날은 32일입니다.

$$
P(\text{비})=\frac{32}{100}=0.32=32\%
$$
:::
```

기본 지원 표기:

| 표현 | 원고 예시 |
| --- | --- |
| 분수 | `\frac{a}{b}` |
| 지수·아래첨자 | `x^2`, `x^{n+1}`, `a_i` |
| 제곱근·n제곱근 | `\sqrt{x}`, `\sqrt[3]{x}` |
| 집합 | `A\cap B`, `A\cup B`, `x\in A`, `A\subseteq B` |
| 조건부 확률 | `P(A\mid B)=\frac{P(A\cap B)}{P(B)}` |
| 한글 설명 | `\text{비가 온 기록 수}` |
| 긴 등식의 명시적 줄바꿈 | `aligned` 환경과 `\\` |

문장 중간의 인라인 수식, 표 안 수식, 제목·카드·Tip·목록 내부 수식은 후속 확장 범위로 구분한다. 첫 구현에서 이런 위치에 수식 표기가 들어오면 지원 위치를 알려 주는 오류를 표시하여 수식 문법이 그대로 인쇄되는 것을 막는다. 코드·프롬프트·실행 결과 안의 달러 기호는 기존 텍스트로 유지한다.

원고 작성 단계에서는 중요한 계산식과 공식은 독립 수식 블록에 놓고, 긴 등식은 의미가 유지되는 지점에서 여러 줄로 작성한다. 일반 본문의 `P(A)`, 숫자, 기호를 앱이 임의로 수식으로 바꾸지는 않는다.

## 4. 구현 순서

### 단계 1 — 실제 Canva에 넣는 작은 실험

본 구현에 앞서 수식 몇 개를 실제 교재 크기의 Canva 페이지에 넣어 핵심 경로를 확인한다.

- 한글이 포함된 확률 분수, `\sqrt{\frac{x-1}{x+1}}`, 지수·아래첨자, 집합·조건부 확률, 여러 줄 등식을 사용한다.
- MathJax의 SVG 출력과 기존 `addPage` 이미지 `dataUrl` 경로를 우선 사용한다. 빈 첫 페이지를 채우는 기존 경로에서도 확인한다.
- SVG에 명시적인 픽셀 크기와 `viewBox`를 넣고, 전역 CSS·외부 글꼴·다른 SVG 파일을 참조하지 않도록 한다. `fontCache: 'none'`을 우선 사용한다.
- 한글을 브라우저에서만 볼 수 있는 `<text>`로 남겼을 때의 호환성에 의존하지 않는다. 배포 가능한 한글 글꼴의 글리프를 path로 만드는 방법까지 검증한다. 글꼴 선택·라이선스·번들 크기를 기록한다.
- 브라우저와 Node CLI에서 같은 수식의 가로·세로 크기가 일치하는지 확인한다. 한글 폭도 같은 글꼴의 실제 치수로 계산한다.
- Canva 편집기 확대와 PDF 내보내기에서 분수선·루트·한글이 깨지거나 잘리지 않는지 확인한다.

완료 기준: 사용자가 제시한 유형의 한글 분수와 루트가 실제 Canva 및 PDF에서 정상 표시된다. 이 결과를 확인한 뒤 렌더러 의존성과 생성 경로를 확정한다. 현재 문서와 SDK 타입에 근거한 가능성 판단을 실제 검증 완료와 구분한다.

### 단계 2 — 수식 파서와 원고 검사

새 `parser/math-block.ts`에서 수식 경계, 원문, 원본 행 범위를 공통으로 읽는다. `ContentBlock`에 `kind: "math"`를 추가한다.

- `$$`의 시작·끝은 독립된 줄로 제한한다.
- 비어 있는 식, 닫히지 않은 블록, 지원하지 않는 위치를 원본 행 번호와 page id로 보고한다.
- 원고 구조 검사와 본문 블록 파서가 같은 수식 판별 로직을 사용한다.
- 수식 내부의 `_`, `|`, `<`, `>`, `#` 등을 Markdown 강조·표·HTML·제목으로 잘못 해석하지 않도록 한다. 기존 코드 펜스 마스크와 수식 영역 마스크를 함께 적용한다.
- MathJax 구문 오류와 지원하지 않는 명령도 원본 수식 위치로 연결한다.
- `BookSpec`을 직접 넘기는 생성 경로에서도 동일한 수식 검증이 실행되게 한다.

완료 기준: 올바른 수식은 보존되고, 잘못된 식은 Canva 페이지를 쓰기 전에 위치와 원인을 알 수 있다.

### 단계 3 — 공통 수식 렌더러와 생성 전 준비

새 `math/render-math.ts`와 `builder/prepare-math.ts`를 중심으로 브라우저와 CLI가 공유하는 렌더러를 만든다.

- 수식 원문을 받아 SVG, 실제 너비·높이, 기준선 정보, 대체 설명을 반환한다.
- 수학 기호와 한글을 자체 완결된 SVG로 만든다. 배경은 투명하게 하고, 색은 앱 테마에서 정한다.
- 엔진과 필요한 글꼴은 프로젝트 의존성·정적 자산으로 공급한다. 런타임 CDN과 외부 수식 변환 서버에 의존하지 않는다.
- 렌더러와 글꼴 버전을 고정하고 lockfile·라이선스 파일을 함께 관리한다.
- 수식 원문·기준 크기·색·글꼴·엔진 버전으로 캐시 키를 만든다. 동일한 식은 재사용하고 본문 글꼴 적용 재시도 때도 다시 렌더링하지 않는다.
- 모든 수식을 검사하고 준비한 뒤 페이지 분할을 시작한다. 하나라도 준비에 실패하면 첫 Canva 페이지 추가 전에 오류를 반환한다.
- SVG와 캐시는 별도 자원 맵으로 전달한다. `BookSpec`에는 원고 정보를 유지하여 생성 재개 지문에 이미지 데이터가 섞이지 않게 한다.
- 렌더러·배치 규칙 변경으로 페이지 구성이 달라지는 경우 기존 생성 기록을 그대로 재개하지 않도록 배치 버전과 원고 지문을 함께 확인한다.

완료 기준: 앱과 CLI가 같은 식에 같은 치수를 사용하며, 조판 오류로 일부 Canva 페이지만 생성되는 상황을 방지한다.

### 단계 4 — 페이지 배치와 Canva 생성 연결

새 `layout/math-block.ts`에서 수식을 하나의 `FlowItem`으로 만들고 `content-flow.ts`에 연결한다.

- 수식은 본문 흐름의 가로폭 안에서 가운데 정렬한다. 실제 조판 크기로 높이와 앞뒤 여백을 확보한다.
- 기준 글자 크기는 본문 28pt에 맞춰 기존 pt→px 변환을 적용한다. 지수·첨자는 수학 조판의 상대 크기를 허용하고, 수식 내부 간격은 수학 조판 규칙을 사용한다. 이 예외를 스타일 규칙에 명시한다.
- 공간 부족을 해결하려고 수식 전체를 자동 축소하지 않는다.
- 남은 높이에 들어가지 않으면 수식 전체를 다음 페이지로 넘긴다. 수식이 페이지 사이에서 잘리지 않게 한다.
- 한 페이지의 안전 영역보다 큰 식은 줄바꿈·분리를 요청하는 배치 오류로 처리한다. 긴 식을 임의로 잘라 수학적 의미를 바꾸지 않는다.
- `aligned`는 저자가 지정한 줄바꿈을 존중해 하나의 블록으로 배치한다.
- 연속 페이지 제목, 수식 바로 앞 소제목, 뒤 문단의 간격까지 고려해 안전 영역을 검사한다.
- 배치 완료 후 기존 규칙대로 쪽번호를 확정한다.
- 생성된 수식은 이미지 자리표시자 목록과 구분한다. 앱에는 수식 준비 진행 상태와 처리한 수식 수를 표시한다.
- SVG 안 글자는 Canva 텍스트 요소가 아니므로 앱이 기준 크기와 글꼴을 관리한다. 기존 본문 글꼴 적용 결과가 수식 글꼴에도 적용됐다고 보고하지 않는다.

완료 기준: 실제 수식 높이가 페이지 수와 쪽번호에 반영되고, 겹침·잘림·자동 축소 없이 Canva에 배치된다.

### 단계 5 — CLI와 원고 작성 규칙 연결

`validate.cjs`의 검증 흐름을 수식 준비 단계와 연결한다. 필요한 비동기 처리를 도입해 수식 렌더러 초기화가 끝난 뒤 결과를 출력한다.

- 일반 `validate`에서도 수식 구문·지원 여부를 확인한다.
- `validate --layout`은 앱과 같은 렌더러의 치수로 페이지 수와 범위를 계산한다.
- `--json` 결과에도 수식 오류의 행 번호·page id와 수식 개수를 포함한다.
- 수식이 없는 원고는 추가 엔진·글꼴 초기화를 생략한다.
- 스킬의 작성·문법·스타일·QA 문서에 수식 규칙을 반영한다. 앞으로 `notes.md`에서 `book.md`를 작성할 때 이 문법을 선택하도록 한다.
- `README.md`, `canva-app/TESTING.md`에 수식 예시, 지원 범위, Canva에서의 편집 방법을 추가한다.

완료 기준: 기존 작업 순서에서 `book.md`를 검증하고 앱으로 생성하면 자동으로 수식 조판까지 실행된다.

### 단계 6 — 기존 원고 적용과 검증

`coala-book-md/ai-math4/book.md`의 주요 수식을 첫 실제 적용 대상으로 삼는다.

- 확률의 기본식, 데이터로 계산한 확률, 조건부 확률의 식, 날씨 데이터 계산식을 수식 블록으로 바꾼다.
- 분수 안의 한글은 `\text{...}`, 조건부 기호는 `\mid`, 교집합은 `\cap`, 백분율은 `\%`로 작성한다.
- 긴 조건부 확률 계산은 여러 줄로 나누거나 단계별 독립 식으로 작성해 28pt 기준으로 읽을 수 있게 한다.
- `notes.md`의 의미와 수치가 유지되는지 확인한다. 교육 내용의 개정은 이 작업에 포함하지 않는다.
- 분할 결과로 해당 단원의 마지막 쪽번호가 달라지면 다른 단원의 `page_start`와 수동 목차의 연결을 확인하고 필요한 값만 갱신한다.

완료 기준: 실제 4단원 원고가 CLI를 통과하고, Canva에서 사용자가 요청한 형태의 수식이 자동 생성된다.

## 6. 후속 확장

별도 줄 수식이 검증된 뒤 인라인 수식과 표 안 수식을 확장한다.

- `inline.ts`에 수식 구간을 추가하고, 텍스트와 수식의 기준선·줄 높이·줄바꿈을 함께 계산한다.
- 목록·강조 상자·카드도 실제 수식 높이로 다시 측정한다.
- 비교 표는 수식 내부 `|`를 열 구분자로 오인하지 않게 파서를 수정하고, 행 높이를 텍스트와 수식의 최대 높이로 정한다.
- 작은 칸에 들어가지 않는 식은 축소 대신 독립 수식 페이지로 옮기도록 안내한다.

## 7. 기술 근거와 아직 검증할 부분

- [MathJax SVG 출력](https://docs.mathjax.org/en/latest/output/svg.html): 수학 조판을 독립 SVG 이미지로 사용할 수 있다.
- [MathJax 독립 SVG 변환 설정](https://docs.mathjax.org/en/latest/web/convert.html): 외부 전역 캐시에 의존하지 않으려면 `fontCache`를 `local` 또는 `none`으로 설정한다.
- [Canva 이미지 생성](https://www.canva.dev/docs/apps/creating-images/): SVG 이미지와 data URL 경로를 지원한다.
- 프로젝트에 설치된 `@canva/design` 타입에는 이미지 요소의 `dataUrl`이 선언되어 있으며, 기존 이미지 배치가 이 경로를 사용한다.

한글 글리프의 SVG path 변환, 기존 `addPage` 및 빈 첫 페이지 경로의 실제 SVG 수용, PDF 내보내기 품질은 단계 1에서 확인할 항목이다. 업로드 API가 필요한 것으로 확인되면 그때 권한·manifest·사용 안내 변경을 계획에 반영한다.
