# AI 디지털 리터러시
## AI와 함께하는 디지털 시대

### 학습 목표

- 생성형 AI의 작동 방식을 설명할 수 있다.
- 일상과 학습 속 AI 활용 사례를 찾을 수 있다.
- AI가 제공한 정보의 신뢰성을 검토할 수 있다.
- 목적에 맞게 프롬프트를 구체화할 수 있다.

### 생성형 AI란 무엇일까?

생성형 AI는 사용자의 질문이나 요청을 받아 글, 그림, 코드처럼 새로운 결과물을 만들어내는 인공지능입니다.
기존의 검색이 이미 누군가 작성해 둔 문서를 찾아 보여주는 방식이었다면, 생성형 AI는 학습한 내용을 바탕으로 그 자리에서 문장을 새로 구성합니다.
그래서 같은 질문을 두 번 물어도 표현이 조금씩 달라질 수 있습니다.
이러한 특성은 아이디어를 빠르게 넓힐 때는 큰 도움이 되지만, 사실 확인이 필요한 정보를 다룰 때는 주의가 필요합니다.
특히 과제와 프로젝트처럼 근거가 중요한 작업에서는, AI가 만들어 준 문장을 완성본이 아니라 초안으로 보고 출처를 직접 확인하는 습관이 필요합니다.
반대로 아이디어를 떠올리거나 막막한 첫 문장을 시작할 때는 부담 없이 여러 번 요청해도 좋습니다.
이 장에서는 생성형 AI를 하나의 도구로 다루는 데 필요한 기본 개념과 태도를 함께 살펴봅니다.
:::

:::page{type="concept" id="how-ai-answers" layout="basic"}
# 생성형 AI는 어떻게 답을 만들까?

AI가 답을 만들어내는 과정을 이해하면, 그 결과물을 왜 검토해야 하는지도 함께 이해할 수 있습니다.

## 1단계 · 입력 이해하기

사용자가 입력한 문장을 작은 단위로 나누어 의미와 의도를 파악합니다.

- 질문의 핵심 주제를 파악합니다
- 요청의 형식과 분량을 확인합니다
- 앞선 대화 내용을 함께 참고합니다

## 2단계 · 다음 말 예측하기

학습한 언어 패턴을 바탕으로 이어질 내용을 한 조각씩 예측해 문장을 완성합니다.

- 가장 자연스러운 표현을 고릅니다
- 매번 조금씩 다른 문장이 나옵니다
- 사실 여부를 스스로 판단하지는 않습니다

## 3단계 · 결과 확인하기

완성된 답변은 사람이 검토해야 비로소 쓸 수 있는 자료가 됩니다.

- 숫자와 고유명사를 먼저 확인합니다
- 출처가 있는 자료와 비교합니다
- 필요하면 조건을 바꿔 다시 질문합니다

> [!KEY_POINT]
> 생성형 AI는 사실을 검색하는 도구가 아니라 가장 그럴듯한 문장을 구성하는 도구입니다. 중요한 정보는 반드시 사람이 확인해야 합니다.
:::

# AI에게 일을 맡기는 네 가지 방법

같은 도구라도 어떤 역할을 맡기느냐에 따라 결과가 달라집니다. 네 가지 활용 방식을 비교해봅시다.

## 정리하기

긴 자료에서 중요한 부분만 남겨 짧게 줄일 때 씁니다.

- 강의 노트 요약
- 회의 기록 정리
- 표로 다시 묶기

## 제안받기

막막한 시작 단계에서 선택지를 여러 개 받아봅니다.

- 발표 주제 후보
- 과제 구성 초안
- 프로젝트 이름

## 바꿔쓰기

이미 쓴 글을 독자와 목적에 맞게 고쳐 씁니다.

- 쉬운 말로 풀기
- 분량 줄이기
- 말투 바꾸기

## 점검받기

내가 만든 결과물에서 빠진 부분을 찾아봅니다.

- 논리 흐름 확인
- 빠진 조건 찾기
- 반대 의견 듣기

> [!TIP]
> 어떤 방법을 쓰든 마지막 판단은 사람의 몫입니다. AI의 답을 그대로 제출하지 말고 한 번 더 다듬어 보세요.
:::

# 프롬프트, 이렇게 바꾸면 달라집니다

질문에 대상과 조건을 덧붙이면 답변의 구체성이 크게 달라집니다. 네 가지 상황을 비교해봅시다.

| 모호한 질문 | 구체적으로 바꾼 질문 |
|---|---|
| 여행 코스 추천해줘 | 2박 3일 부산 여행 코스를 비 오는 날 실내 활동 위주로 추천해줘 |
| 발표 자료 만들어줘 | 대학 신입생 대상 5분 발표용 슬라이드 구성을 5장으로 제안해줘 |
| 코드가 안 돼 | 파이썬 버튼 클릭이 동작하지 않는 흔한 원인을 초보자에게 설명해줘 |
| 글 좀 다듬어줘 | 아래 자기소개 문단을 300자 이내로 줄이고 존댓말로 바꿔줘 |

> [!TIP]
> 대상, 상황, 조건, 분량을 함께 적어 주세요. 네 가지 중 하나만 더해도 답변의 방향이 또렷해집니다.
:::

# 같은 주제를 두 가지 질문으로 물어보기

먼저 떠오르는 대로 짧게 질문한 뒤, 같은 주제에 대상과 조건을 덧붙여 다시 질문해봅시다.
두 답변을 나란히 놓고 어떤 부분이 달라졌는지 표시해 보면, 질문의 어떤 요소가 결과를 바꾸었는지 확인할 수 있습니다.

> [!TIP]
> 질문을 고칠 때는 한 번에 하나씩만 바꿔 보세요. 무엇이 결과를 바꾸었는지 구분하기 쉬워집니다.
:::

# 실습 결과 점검하기

활동을 마친 뒤 다음 항목을 스스로 확인해봅시다. 표시하지 못한 항목이 있다면 해당 단계로 돌아갑니다.

- [ ] 짧은 질문과 구체적인 질문을 각각 작성했다
- [ ] 두 답변의 차이를 세 가지 이상 찾았다
- [ ] 답변에서 확인이 필요한 정보를 표시했다
- [ ] 조건을 추가해 질문을 한 번 이상 수정했다
- [ ] 수정 전후의 답변을 비교해 기록했다
- [ ] 최종 질문을 다시 쓸 수 있게 정리했다

> [!TIP]
> 확인하지 못한 항목은 실패가 아니라 다음에 연습할 목표입니다.

# 파이썬 GUI 첫걸음
## 화면으로 만나는 프로그램

### 학습 목표

- GUI 프로그램의 기본 구조를 설명할 수 있다.
- 창, 위젯, 이벤트의 관계를 구분할 수 있다.
- 간단한 입력과 출력 화면을 만들 수 있다.
- AI의 도움을 받아 오류를 해결할 수 있다.

### GUI란 무엇일까?

GUI는 Graphical User Interface의 줄임말로, 글자를 입력해 명령하는 대신 버튼과 입력창처럼 눈에 보이는 요소를 눌러 프로그램을 사용하는 방식입니다.
우리가 평소 쓰는 대부분의 앱이 이 방식을 따릅니다.
파이썬에서는 표준 라이브러리인 Tkinter를 이용해 별도의 설치 없이 창을 띄우고 버튼을 배치할 수 있습니다.
처음부터 완성된 화면을 한 번에 만들려고 하기보다, 빈 창을 먼저 띄워 보고 요소를 하나씩 추가하며 실행 결과를 확인하는 방식이 훨씬 빠릅니다.
오류 메시지는 무엇이 잘못되었는지 알려 주는 가장 정확한 단서이므로, 그대로 읽어 보고 필요하면 AI에게 원인을 물어보는 것도 좋은 방법입니다.
이 장에서는 창을 만들고, 화면에 요소를 올리고, 사용자의 동작에 반응하게 하는 세 단계를 차례로 익힙니다.
:::

:::page{type="concept" id="gui-parts" layout="basic"}
# GUI 프로그램을 이루는 세 요소

## 창(Window)

프로그램의 모든 요소가 놓이는 바탕이 되는 영역입니다.

- 제목과 크기를 정합니다
- 화면에 계속 떠 있도록 유지합니다
- 닫으면 프로그램이 끝납니다

## 위젯(Widget)

창 위에 올리는 버튼, 입력창, 글상자 같은 개별 구성 요소입니다.

- 역할에 맞는 종류를 고릅니다
- 배치 방식으로 위치를 정합니다
- 필요할 때 내용을 바꿀 수 있습니다

## 이벤트(Event)

클릭이나 입력처럼 사용자가 만든 동작과 그에 대한 반응입니다.

- 어떤 동작에 반응할지 정합니다
- 실행할 함수를 연결합니다
- 결과를 다시 화면에 보여줍니다

> [!KEY_POINT]
> 창을 만들고, 위젯을 올리고, 이벤트를 연결합니다. 모든 GUI 프로그램은 이 세 단계의 반복으로 이루어집니다.
:::

:::page{type="concept" id="common-widgets" layout="cards"}
# 자주 쓰는 위젯 살펴보기

화면을 구성하기 전에 어떤 위젯이 어떤 일을 맡는지 정리해 둡시다. 역할을 먼저 정하면 배치가 쉬워집니다.

## Label

화면에 글자를 보여주는 가장 기본적인 위젯입니다.

- 안내 문구 표시
- 계산 결과 출력
- 상태 메시지 안내
- 이미지도 넣기

## Entry

사용자가 한 줄짜리 값을 입력하는 칸입니다.

- 이름이나 숫자 받기
- 입력값 읽어오기
- 기본값 미리 넣기
- 비밀번호 가리기

## Button

누르는 순간 연결된 함수를 실행하는 위젯입니다.

- 계산 시작하기
- 입력값 저장하기
- 화면 내용 지우기
- 창 닫기

## Frame

여러 위젯을 한 덩어리로 묶어 정리하는 상자입니다.

- 영역 나누기
- 함께 배치하기
- 한 번에 숨기기
- 구조 알아보기
:::

:::page{type="comparison" id="layout-comparison"}
# 배치 방식 세 가지 비교

위젯을 화면에 올리는 방법은 여러 가지입니다. 만들려는 화면의 형태에 따라 알맞은 방식을 고릅시다.

| 배치 방식 | 어울리는 화면 | 주의할 점 |
|---|---|---|
| pack | 위에서 아래로 쌓는 단순한 화면 | 세밀한 위치 조정이 어렵다 |
| grid | 행과 열이 있는 입력 양식 | 행과 열 번호를 미리 계획해야 한다 |
| place | 좌표를 직접 정하는 자유 배치 | 창 크기가 바뀌면 흐트러진다 |
:::

:::page{type="practice-opening" id="practice-002-1" practice="002-1" practice-kind="GUI 실습" platform="알고플로에서 실습하기"}
# 이름을 입력하면 인사하는 창 만들기

입력창에 이름을 적고 버튼을 누르면 화면에 인사말이 나타나는 작은 프로그램을 만들어봅시다.
창을 띄우는 것부터 시작해 위젯을 하나씩 올리고, 마지막에 버튼과 함수를 연결합니다.

- [ ] 제목과 크기를 정한 창을 띄울 수 있다
- [ ] 입력창과 버튼을 원하는 위치에 배치할 수 있다
- [ ] 버튼에 함수를 연결할 수 있다
- [ ] 입력값을 읽어 화면에 다시 보여줄 수 있다
:::

:::page{type="practice-checklist" id="project-check"}
# 프로젝트 제출 전 점검표

- [ ] 창 제목과 크기를 목적에 맞게 정했다
- [ ] 필요한 위젯을 빠짐없이 배치했다
- [ ] 버튼이 의도한 함수와 연결되어 있다
- [ ] 입력값이 비었을 때의 동작을 확인했다
- [ ] 결과가 화면에 바르게 표시된다
- [ ] 오류 메시지와 해결 과정을 기록했다
- [ ] AI에게 받은 코드를 직접 설명할 수 있다
- [ ] 파일 이름과 제출 형식을 확인했다

> [!TIP]
> AI가 준 코드는 붙여 넣기 전에 한 줄씩 읽고 직접 설명해 봅시다.
:::
